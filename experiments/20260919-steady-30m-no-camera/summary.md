# 摄像头采集与 YOLO 对 RK1828 文本推理的影响

## 实验定义

本组与 `20260919-steady-30m-single-camera` 使用相同的 30 分钟、四 Session、5 秒周期和 16 轮上下文刷新配置。唯一主动变量是关闭 cam0 采集和 YOLO；cam1 在两组中均禁用。

需要严格说明：禁用输入源后，视觉服务仍用最后一帧维持 Mosaic/Focus 合成及 MPP 编码。因此本组是“关闭摄像头采集、RGA 前处理和 YOLO，保留媒体服务”的基线，不是完全停止视觉服务。cam0 的源帧和检测完成计数在 30 分钟内均没有增长，证明采集与 YOLO 确已停止。

## 正确性

两组均完成 360 次有效推理（24 Prime + 336 Recall），正确率均为 100%，错误和会话串话均为 0；Recall 的复用 Token 分布完全一致，平均 242.36、P50 237、P95 427，输入负载可比。

## A/B 对照

| 指标 | cam0 60 FPS + YOLO 5 FPS | 关闭采集与 YOLO | 变化 |
| --- | ---: | ---: | ---: |
| Recall TTFT P50 | 95.110 ms | 94.973 ms | -0.14% |
| Recall TTFT P95 | 96.895 ms | 96.445 ms | -0.46% |
| Recall端到端 TTFT P50 | 101.594 ms | 101.336 ms | -0.25% |
| Recall端到端 TTFT P95 | 104.215 ms | 103.259 ms | -0.92% |
| Recall TPOT P50 | 11.269 ms | 11.163 ms | -0.94% |
| Recall Decode TPS 均值 | 87.823 | 89.385 | +1.78% |
| Prime TTFT P50 | 179.282 ms | 178.535 ms | -0.42% |
| 视觉服务 CPU 均值 | 52.53% | 27.23% | -25.30 个百分点 |
| 视觉服务 CPU P95 | 57.43% | 32.89% | -24.53 个百分点 |
| 温度均值 | 37.14 °C | 34.42 °C | -2.73 °C |
| 温度 P95 | 37.92 °C | 35.15 °C | -2.77 °C |

## 结论

RK3588 摄像头采集和 5 FPS YOLO 对 RK1828 的 PCIe 大模型推理干扰很小：Recall TTFT P50/P95 的差异均小于 0.5%，端到端 TTFT P95 改善约 0.92%。Decode TPS 均值提高 1.78%，但两组存在少量低速离群 Token，因此后续应至少重复三次并报告置信区间，不能把单次均值差直接解释为确定的加速。

系统侧收益明确：关闭采集与 YOLO 后，视觉进程 CPU 平均值下降 25.30 个百分点，板端平均温度下降 2.73 °C。残余约 27% CPU 主要来自持续运行的合成和 MPP 输出，这暴露出一个实际优化点：没有在线输入源或浏览器订阅时，应让 Mosaic/Focus 编码链路进入休眠，而不是重复编码最后一帧。

两组推理 RSS 起点不同，且是顺序实验，绝对 RSS 均值不适合直接做因果比较。视觉服务 RSS 两组均固定为 70.09 MiB，未发现增长。

## 下一步

1. 为视觉服务增加“无输入源且无订阅者时暂停合成/MPP”的空闲门控，并记录唤醒延迟。
2. 进行三轮 10 分钟交错 A/B/A/B 试验，计算均值、标准差和 95% 置信区间，排除热状态与运行顺序影响。
3. 进行真实图片输入并行实验，补充图片分辨率、视觉 Token、预处理、Vision Encoder、Embedding、TTFT 和 TPOT 全链路数据。

实验结束后 cam0 已恢复启用并在线；cam1 仍保持禁用。

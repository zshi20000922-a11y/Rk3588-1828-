# 常驻多模态缓冲区复用验收

## 改动

将每次图像请求创建的 392×392 RGB888 预处理缓冲区、`196×2048` FP16 视觉 Embedding，以及可变长度音频 Embedding 移入常驻 `RknnEngine::Impl`。串行 RK1828 队列保证同一时刻只有一个请求使用这些缓冲区，因此不会引入并发覆盖。

## 五次真实请求

| 指标 | 均值 | 最小 | 最大 |
| --- | ---: | ---: | ---: |
| 图片读取 | 27.12 ms | 23.87 ms | 32.11 ms |
| 图像预处理 | 5.46 ms | 4.51 ms | 7.17 ms |
| Vision 总计 | 234.58 ms | 230.62 ms | 239.88 ms |
| LLM TTFT | 289.88 ms | 283.63 ms | 294.88 ms |
| 端到端 TTFT | 645.34 ms | 631.75 ms | 664.39 ms |
| 请求总耗时 | 810.29 ms | 797.74 ms | 826.75 ms |
| Decode TPS | 84.91 | 81.86 | 86.39 |

五次回答均为 15 Token，避免输出长度变化干扰比较。守护进程测试后保持在线。RSS 从 58,660 kB 增至 74,564 kB，`VmHWM` 前后均为 113,696 kB，没有产生新的内存峰值。该结果只证明短序列稳定性，不能单独证明不存在泄漏；后续仍执行 100 次请求和 30 分钟压力测试。

此前只有单次同图基线且包含首次请求效应，因此本轮不宣称确定的加速百分比。下一轮应以旧/新二进制分别预热后交替运行相同输入，并报告 P50、P95 和置信区间。

# RKNN3 常驻服务首轮基线

## 目的

验证 Qwen2.5-Omni 权重在 RK1828 上只加载一次、不同 `conversation_id` 使用独立 Session，并确认文本、图像、音频、图音联合与 KV 复用链路。

## 已验证结果

| 场景 | 输入 Token | 输出 Token | 复用 Token | 记录到的 LLM 阶段耗时 |
|---|---:|---:|---:|---:|
| 文本第一轮 | 52 | 11 | 0 | 301.06 ms |
| 同会话第二轮 | 15 | 9 | 62 | 187.98 ms |
| 图像 | 244 | 15 | 0 | 440.44 ms |
| 音频 | 122 | 8 | 0 | 267.25 ms |
| 图像+音频 | 315 | 32 | 0 | 733.24 ms |

第二轮 `n_reuse_tokens=62`，证明多轮 KV Cache 已在真实 RKNN3 Session 中复用。图像回答识别出月球上的宇航员与啤酒瓶；音频转写为“图片里是什么”；联合输入给出与语音问题相关的图像描述。

上述旧版 `total_ms` 计时点位于多模态编码之后，实际只代表 LLM Session Run，不能作为端到端延迟。后续版本已拆分 `vision_ms`、`audio_ms`、`ttft_ms`、`llm_ms` 和 `total_ms`，该表保留原始口径并明确标注。

新计时实现的单次图像冒烟结果为：Vision 263.39 ms、TTFT 286.41 ms、LLM 398.32 ms、端到端 775.01 ms、Decode 98.29 token/s。该结果仅为一次冒烟，不作为统计结论。

## 发现与修复

1. Runtime 实际只发现 1024-token KV group，请求 8192 时自动降到 1024；界面和配置已经改为真实值。
2. Daemon 初版 SIGTERM 后阻塞在 `accept()`，热更新会导致新 Context `MODEL_SETUP ACK_FAIL`；现已在信号处理时关闭监听 FD。
3. 浏览器录音为 WebM，而模型读取 WAV；上传接口现在用 FFmpeg 转为 16 kHz 单声道 WAV。
4. 联合输入最初只读取第一个附件；现按扩展名分别路由图像和音频附件。

## 结论

常驻、多 Session、KV 复用与三种多模态链路均已在 RK3588 + RK1828 真机通过。下一组正式实验必须使用新指标结构重新采样，并增加重复次数与 P50/P95。

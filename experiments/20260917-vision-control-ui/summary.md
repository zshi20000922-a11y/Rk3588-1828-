# 视觉流水线控制与摄像头放大验收

## 目标

把 RK3588 视觉服务的帧差、运动门控、YOLO 检测和追踪能力暴露为受控 Web 操作，同时为真实 IMX415 画面增加双击放大与全屏入口。

## 实现

- FastAPI 提供 `GET/PATCH /api/v1/vision/pipeline`，只接受白名单字段和合法 FPS 范围。
- 后端先保存原配置，再以原位标量替换更新 YAML；通过 Unix Socket 调用 `reload_soft_config`，失败时恢复原文件。
- 页面显示四个独立状态开关。操作写入已有审计日志。
- 放大同一路摄像头时，缩略图替换为占位文字，只保留放大画面的一条 MJPEG 连接。

## 真机结果

四个布尔配置均完成关闭、开启和状态回读，最终恢复为全部开启。YOLO 暂停期间，RTSP 探测仍返回 H.264、1920×1080，说明检测控制没有中断编码输出。浏览器 DOM 验收确认四个按钮均为可操作状态，双击 IMX415 后仅存在一个该摄像头画面元素。

## 遇到的问题与修复

最初使用 `yaml.safe_dump` 重写配置，板端视觉服务的轻量 YAML 解析器报 `expected key:value at config line 46`。根因是序列化结果改变了原文件布局。改为仅替换目标标量，并加入热加载失败回滚后通过验收。

## 结论与下一步

控制面与视频数据面已经解耦，适合作为后续消融实验的可控变量。下一阶段接入可配置 RTSP/文件视频源，并测量 RK3588 MPP 硬解码、转码及 WebRTC/HLS 网关的吞吐与延迟。

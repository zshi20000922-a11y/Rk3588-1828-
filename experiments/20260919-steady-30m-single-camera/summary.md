# RK3588 + RK1828 单摄像头 30 分钟稳态实验

## 结论

Qwen2.5-Omni-3B 在 RK1828 上以四个独立 Session 连续运行 30 分钟，共完成 360 次有效推理，正确率 100%，错误和会话串话均为 0。RK3588 同时维持 cam0 约 60 FPS 采集及 5 FPS YOLO 检测，采集丢帧、超时和重连均为 0。cam1 全程保持禁用，其重连计数固定为 168，未再访问被其他任务占用的摄像头。

## 条件与口径

- 请求周期 5 秒，四会话轮询；每个会话每 16 次召回后清理并重新建立上下文。
- 24 次 Prime 请求负责写入会话代号；336 次 Recall 请求验证 KV 复用和会话隔离。
- Prime 输入为 58–60 Token，Recall 新输入固定 20 Token；Recall 平均复用 242.36 Token。
- 本实验是文字 KV 稳态及摄像头并行负载实验，不包含图片输入，因此视觉 Token、图片预处理和 Vision Encoder 时间均为 0。
- `TTFT` 是 RKNN LLM 阶段首 Token 延迟；`end_to_end_ttft` 还包括文本 Embedding 和请求侧固定开销；`TPOT` 按首 Token 后的生成 Token 计算。

## 推理结果

| 场景 | 数量 | TTFT P50/P95 | 端到端 TTFT P50/P95 | TPOT P50/P95 | Decode TPS 均值 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Prime（无 KV 复用） | 24 | 179.28 / 185.68 ms | 264.65 / 294.66 ms | 11.02 / 12.64 ms | 88.86 |
| Recall（KV 复用） | 336 | 95.11 / 96.89 ms | 101.59 / 104.22 ms | 11.27 / 12.57 ms | 87.82 |

KV 复用使 LLM TTFT P50 从 179.28 ms 降至 95.11 ms，下降 46.9%；端到端 TTFT P50 从 264.65 ms 降至 101.59 ms，下降 61.6%。Decode TPS 基本不变，说明收益主要来自减少 Prefill，而非改变 Decode 性能。

- 通过：本地自动测试 10/10。
